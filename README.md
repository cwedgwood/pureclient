# Go API client for Everpure FlashArray

Unofficial, community-maintained Go client for the Everpure (formerly
Pure Storage) FlashArray REST API v2.26.

> **Note on naming.** Pure Storage rebranded to Everpure in early 2026.
> Many artifact names that predate the rebrand still use the old
> branding - the spec image at `quay.io/purestorage/swagger`, the
> `purestorage` namespace in URLs, internal symbol names in the
> generated client, and so on. They all refer to the same vendor.

The client is generated by
[oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from the
OpenAPI 3 spec at `client/api/openapi.yaml`. That spec was derived
from the community `quay.io/purestorage/swagger` image (see
`client/api/openapi.yaml` header comment for provenance).

## Installation

```sh
go get github.com/cwedgwood/pureclient/client
```

```go
import pureclient "github.com/cwedgwood/pureclient/client"
```

Requires Go 1.20 or newer.

## API reference

The generated client carries the upstream Pure-authored field
descriptions as Go doc comments. There is no separate generated
`docs/` tree (the previous swagger-codegen client had one; it was
boilerplate restating the spec and nobody used it).

- **Go reference (online):** https://pkg.go.dev/github.com/cwedgwood/pureclient/client
  and https://pkg.go.dev/github.com/cwedgwood/pureclient/auth.
  Renders the Pure field descriptions, all types, and all
  operations. Available once a release tag is published.
- **Go reference (offline):** `go doc -all ./client/ ./auth/ | less`,
  or focused lookups like `go doc github.com/cwedgwood/pureclient/client.Volume`.
- **HTTP / spec view:** `client/api/openapi.yaml` is the OpenAPI 3.0.1
  source of truth. Render it interactively with any OpenAPI tool, e.g.
  `npx @redocly/cli preview-docs client/api/openapi.yaml`, or load it
  into <https://editor.swagger.io/>. The file's header comment
  records provenance.
- **Raw grep:** `client/client.gen.go` holds every operation method;
  `client/types.gen.go` holds every type.
  `grep 'WithResponse(ctx' client/client.gen.go` enumerates the API
  surface in a few seconds.

Note that oapi-codegen emits sparse comments on operation methods
(e.g. `// GetApi226VolumesWithResponse request returning *GetApi226VolumesResponse`);
the rich per-operation descriptions in the spec do not currently
propagate into the generated code. Use the spec for HTTP-level
detail.

## Regenerating

```sh
make generate                  # use existing client/api/openapi.yaml
make generate VERSION=FA2.42   # extract a Swagger image spec (OAS3 only)
```

The `VERSION=FA2.NN` form only works for OAS3 specs (FA2.42 and
later). Earlier versions, including the currently-committed FA2.26,
are Swagger 2.0 and require a one-shot Swagger 2.0 -> OpenAPI 3.0.1
conversion that `generate.sh` does not automate. To regenerate
against FA2.26 specifically, re-use the already-converted
`client/api/openapi.yaml` (the default no-arg form).

The extraction form rewrites `client/api/openapi.yaml` with the
freshly-extracted spec (plus a regenerated provenance header) so
the committed spec and the committed client stay in sync. The
local-file form (`./generate.sh /path/to.yaml`) regenerates the
client but does **not** touch `openapi.yaml` - use it for local
experiments only.

See `generate.sh` for details. Requires `oapi-codegen` v2.7.0 (the
version used for the committed output); Docker is only needed when
extracting a spec by version.

## Caveats

- Many composed (`allOf`) nested objects are emitted as
  `map[string]interface{}` rather than typed structs. See MIGRATION.md.
- Generated method names follow URL structure
  (`GetApi226VolumesSpaceWithResponse`) and may shift on future regens.
